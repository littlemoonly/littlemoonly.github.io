预训练数据的总体数据量会达到 10T tokens 的量级

#### 一个典型的预训练数据构建流程

数据收集 → 数据清洗 →质量打分 →去重 →多样性采样 →数据混合 →Tokenize

### 1. 数据清洗

#### 语言识别：FastText

FastText 模型是一种轻量级的文本分类模型，它可以用于语言识别，输出类别（'en'）及置信度

- **N-gram 特征**：是文本中连续出现的N个字符或词。例如`机器学习`的特征就是：机器、器学、学习
- **N-gram 语言模型**：是传统的统计语言模型，它使用前 `N - 1`个词预测下一个词的概率

### 模型打分

利用规则或者质量分类模型，对文本进行打分

可以过滤乱码广告，低质量文本

### 数据多样性采样

**原因&目的：**

原始 SFT 数据集样本量大，如果全部用于SFT：1. 数据之间可能存在大量语义冗余、2. 可能耗费过多计算资源、3. 导致任务分布不均匀（还要考虑是否与目标任务的实际分布一致）

#### 1.SFT 数据采样

目的是得到 **核心样本（Core Samples）**，我们希望以尽可能少的样本，代表原始数据的整体分布；它们最好覆盖所有知识类型，同时可以减少样本之间的相似性。

**方法：**

> *Maybe Only 0.5% Data Is Needed*

1. **Encoding ：**将一个任务文本中的所有 token 编码为向量
   eg. 假设文本 `求解方程 x² - 4 = 0` 有 20个 token，模型隐藏维度是768，经过 embedding model 后 ，被编码为 20 个768 维向量
2. **Mean Pooling**：对 token 维度取平均，得到句子级向量
   eg. 20 x 768 被平均为 1x768
3. **L2 Normalization**：将句子向量长度归一化为 1， 方便后续计算向量相似度
4. **Projecting & Clustering**：将样本表示为向量空间中的点，执行 K-means 聚类
   这一步，找到**样本数量最多的**聚类中心，找到距离该中心最近的点作为**采样初始点**
5. **K-Center Greedy**：因为我们希望采样到的样本尽可能覆盖更广的任务范围，所以每次选距离**已选点集合**最远的样本，不断重复直到选出规定数量的 Core Samples

## 2.3 预训练流程

### Tokenizer 的训练

定义**压缩率**：$R=\frac{\text{字符数}}{\text{Token 数}}$

中文 1 token ≈ 1.5 汉字

压缩率过低：token 数量多，训练和推理的成本增加

压缩率过高：通常需要更大的词表，低频率 token 难以充分训练

保留余量：tokenizer 的 vocab_size 应该比模型词表大小要少，留出1000个左右，用于后续对其现任中的全新 token

### Scaling Law

注意条件是稠密的Transformer

D 为 训练使用 Token 数，N 是模型参数量
$$
FLOPs = 6 * D * N
$$
**核心问题：固定计算预算，如何平衡模型大小与训练数据量？**

- 模型过大：可训练的 Token 不足，模型训练不充分。
- 模型过小：模型容量有限，即使训练更多 Token，效果也可能受限。

### MHA、MQA、GQA

（原理就像 cache 缓存中的 直接映射、全相联映射、组相联一样）

- **原始的 MHA :** 每个 head 的 Q 矩阵都有不同的 KV 矩阵对应
- **MQA（Multi-Query Attention）**:
  MQA就是所有的Qhead的矩阵都共用相同的K V head矩阵
- **GQA（Grouped Query Attention）**
  将 n_head 个Q矩阵分成若干组，每个组内共用相同的K V矩阵

### 混合精度训练

明确：前向传播计算得到 loss， loss.backward() 得到梯度，step 根据梯度更新权重

- FP32 用于参数更新（主权重、优化器状态）；主权重就是`optimizer.step()`更新的权重
- BF16用于**计算**，也就是实际参与前项传播和反向传播计算的**权重**

#### 经典 FP16 混合精度方案

以训练 7B 模型为例：

显存占用情况计算

- 不含 activation：
  每个参数=14B
  本身主权重（FP32）：4B、计算权重（BF16）：2B
  优化器：梯度 4B、一阶动量、二阶：2***2B**
- 含有 activation

### Loss Scaling 

**为什么需要？**：FP16 表示极小数的能力有限，微小梯度可能下溢为 0。

**方法：** 前项传播时得到的loss先放大 2^loss_scale 倍，之后反向传播得到梯度后，先检查是否出现了上溢出，然后再除以 2^loss_scale 

### Data Paralizing

**DP（数据并行）**：每张 GPU 处理不同数据，反向传播后同步梯度。

### 长文本继续与训练

训练时，一次处理的 token 数量会从 4096 增加到 16384（也就是 `seq_len` ）

**要解决的问题：**模型原来只能处理 4K Tokens，如何继续训练，让它能有效处理 16K 甚至更长的 Tokens？

Code Llama 采用了 Long Context Fine-Tuning（LCFT） 的方法。

#### RoPE

RoPE 旋转的角度公式
$$
\omega_i = \theta ^{-2i / d}
$$
将 RoPE 位置编码中的 $\theta$ 从 10000 扩大到 100,0000，通过**降低旋转频率，延长旋转周期**，让模型更有机会学到较远 Token 之间的注意力关系

## 2.4 预训练评估

全是字、没有词的 tokenizer，Loss 往往最低：因为在 token 上作 loss 的平均，除以的 N 大

### PPL 困惑度 Perplexity

 \[ L=-\frac{1}{N}\log P(\text{整个句子}) \] 

衡量模型对下个token预测概率有多自信

### 大海捞针 NIAH（Needle in A Haystack）

在长文本中插入指定信息，检查模型是否能够准确检索
